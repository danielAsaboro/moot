# Moot
One line: a company brain that audits the reasons behind your standing decisions and tells you which ones have expired, with the evidence path.
For / Job / Done: engineering lead inheriting a team's rules / "which decisions still hold, which have an expired reason, where is the proof?" / a ledger of verdicts, each with the traversal path, citations and an approval-gated re-open memo; orphaned decisions routed to a successor; what-if and riskiest reasons.
Sponsor mechanism (critical path): FalkorDB named graph per tenant; verdicts are `ro_query` path queries over Decision → Premise ← Evidence with validity windows; PageRank/SPpaths/WCC as tools; Findings written back as nodes.
Features in scope (5): graph + seven read-only tools (incl. timeline) · corpus + idempotent ingest · audit agent with validated narration · evals vs BM25 and random, noise scaling, verdict accuracy · web UI with rot chart, depth toggle, graph and Cypher views, approval gate · upgrades: orphaned-decision handover (REPORTS_TO walk), re-open memo + Approve, what-if + riskiest reasons · real-world proof: 25 public ADRs in graph public_adrs (moot/realworld, GitHub + OSV checks, snapshot in data/realworld) · agent gate: check_action / GET /api/gate (ALLOW · DENY · REVALIDATE, depth 6, read-only), dated SUPERSEDES / RETIRES, eval/eval_gate.py · backtest: 722 real decisions from 30 public repos' ADR git history, labels = maintainers' own status changes, gate replayed monthly in graph `backtest` (moot/backtest, eval/eval_backtest.py, snapshot in data/backtest).
Not building: live Slack/Jira connectors, auth, graph editing in the UI, embeddings.
Stack: Python 3.11+, falkordb client, FastAPI, Next.js (TypeScript, App Router, static export in frontend/, served by FastAPI; three.js via React Three Fiber), moot/llm.py (Groq tool calls for routing and narration, Anthropic as the alternative, daily spend cap; never verdicts), mcp.
Run: `make db && make seed && make ui && make serve` (UI dev: `make ui-dev`, API on :8000, UI on :3000) · Test: `make test` · Eval: `make eval` · Verify README numbers: `make verify` (studies and withdrawn results: docs/studies.md) · Deploy: Dockerfile + docker-compose (FalkorDB sidecar).
Repo map: moot/ (graph.py seed, tools.py queries, verdict.py pure logic, agent.py narration, answer.py question -> one read-only tool, mapdata.py the map export (GET /api/map), people.py who-knows-why/departure/bus factor on a KNOWS projection, connectors/github.py `moot ingest-github`, connectors/reasons.py stated reasons from ADR text (model proposes, literal-span validator keeps, cached in data/github/<repo>/reasons.json), api.py, mcp_server.py, corpus/ spec+generator, ingest/ build_graph+extract) · frontend/ Next.js UI (landing page at /, Ask at /app, ledger at /app/ledger, transit map at /app/map; `npm run build` exports to frontend/out) · web/ legacy UI at /legacy · data/ corpus, truth.json, graph.json · eval/ · docs/falkordb.md.
Invariants (never): never let the model write Cypher · never let the model touch the database · never write to the graph without an approval call · never cite an id the rows did not return · never change a verdict without a dated edge.
Design: follow design.md.
Rules that disqualify: FalkorDB must be load-bearing (it is: verdicts are path queries); README must carry the graph model and the Cypher; AI use must be disclosed.
Evidence rules: a claim is done only when a committed eval or test backs it; mocks are never evidence.
