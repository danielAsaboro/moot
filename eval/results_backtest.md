# Backtest: real decisions, judged by their own maintainers

Generated by `make backtest` (re-score offline with `python3 eval/eval_backtest.py`). Histories read on 2026-10-17.

**The question.** Rewind a real repository to any past month, show Moot only what existed then, and ask its agent gate whether an agent may act on each decision. Did it say DENY before the repository's own maintainers abandoned the decision?

**The answer key, written by neither of us.** The git history of the ADR folders of 30 public repositories. A decision dies on the commit where its own repository marked it superseded, deprecated or invalidated, moved it to an archive folder, or titled a later ADR as dropping the tool it picked. The key never enters the graph: Moot sees no retirement edges, only dated evidence about the tools.

## Coverage first

- 722 decisions were in force at some point; **23** were later abandoned by their own repository (17 more arrived already dead, with no date, and are left out).
- 97 of them (13%) pick an outside tool in their title. Only those can be checked from outside, and only **6 of the 23** deaths fall among them.
- So outside evidence can speak to at most 26% of the decisions real teams abandon. The rest die for internal reasons, which is what the Larkspur company graph (tickets, chat, PRs) is for.

## Score on the decisions that pick a tool

97 decisions, 6,013 decision-months, each gate call a dated path query against the FalkorDB graph `backtest`. Intervals are 95% bootstrap over decisions.

| method | caught before maintainers | missed | median lead | flagged while still listed in force | share of flags later confirmed |
|---|---|---|---|---|---|
| **Moot gate (DENY)** | **2 / 6** (recall 0.33, 0.00–0.80) | 4 | 892.5 days | 22 of 91 | 0.08 (0.00–0.21) |
| trust the ADR | 0 / 6 | 6 | – | 0 of 91 | 0.00 |
| age ≥ 3 years | 3 / 6 | 3 | 329 days | 73 of 91 | 0.04 |
| random, same number of flags (mean of 200) | 1.4 / 6 | 4.6 | – | 22.6 | 0.06 |

**Read it plainly.** Six deaths is too few to rank methods on recall: the intervals overlap, and Moot catches about what a random flagger with the same budget would. The key was fixed before the gate ran. What separates the methods is the flags on decisions still listed as in force, which the key cannot grade. The age rule raises 73 of them with no reason attached. Moot raises 22, each naming a dated fact a reviewer can check in a minute, and reading them one by one (below) gives: **15** real, **4** right, **2** false alarm, **1** mixed. *Right* means the repository itself later moved off the tool in another document without retiring the ADR; *mixed* means it said so but the code disagrees; *real* means the premise did die upstream and the repository has not said what it will do about it.

## What the evidence is, and what is left out

- **Maintained**: the default branch of each tool's own repository, cloned from GitHub (72 tools). A gap of 365 days without a commit CONTRADICTS “<tool> is actively maintained” on the day the gap reaches 365 days; the next commit SUPPORTS it again, which the gate reads as REVALIDATE. The same 365-day rule as the live checker (`moot realworld`).
- **Open source**: the vendors' own license announcements, dated (`moot/backtest/tools.py`, LICENSE_EVENTS).
- **Left out**: the live checker's vulnerability premise. OSV dates when an advisory was published, but not which release a team was on at a past date, so it cannot be replayed without guessing.
- **Limits**: tools are matched on ADR titles only (bodies name the tools they rejected too); ADRs that were imported in bulk use the date written in the ADR, or are left out when they arrived already dead; “not abandoned” means only that nobody wrote it down.
